# Tidy 开发路线图

> 最后更新：2026-07-28 | 版本：v0.1
> 文档状态：草案

本文档是 Tidy 项目阶段推进的最高权威，定义每个阶段的战略目标、边界（IN / OUT）、依赖关系和 Exit Gate。下游文档（阶段需求、设计、测试用例表、实现计划）不得扩大、缩小或改变本路线图边界；需要改变边界时必须先修改本文档。

阶段文档的创建顺序、命名规则和同步规则见 [docs.md](../docs.md)；功能优先级、模块组织和状态机定义见 [Tidy 窗口管理 App 功能列表](Tidy%20窗口管理%20App%20功能列表.md)；市场定位、竞品、风险和商业模式见 [Tidy 窗口管理 App 市场调研报告](Tidy%20窗口管理%20App%20市场调研报告.md)。

> **维度说明**：本文档中的 `P0` / `F{n}` 指**开发阶段编号**（Phase），与 [Tidy 窗口管理 App 功能列表](Tidy%20窗口管理%20App%20功能列表.md)中的 `P0/P1/P2` **功能优先级**（Priority）是独立维度，不可混淆。

## 1. 产品验证目标

Tidy 必须验证的核心问题：

> 目标用户是否会反复使用"铺开 → 选择 → 还原"，并认为它比 App Exposé 或普通窗口切换器更快？

v0.1 默认作用域：

- 当前焦点所在屏幕
- 前台 App
- 当前 Space 中 2～9 个可见、可操作窗口
- 单次会话
- 一个固定热键
- 选中后临时放大（Temporary Maximize）

## 2. 阶段定义

### P0_技术探针（准备阶段）

**战略目标**：证明核心技术栈可行，建立可编译的项目骨架，为功能开发扫清技术风险。

| 维度 | 内容 |
|------|------|
| IN | AX 权限检测与监听、窗口枚举（CGWindowList + AX 匹配）、AXSetFrame 兼容性验证、AX 焦点窗口获取、Carbon 全局热键、CGEventTap 生命周期、Input Monitoring / Event Access 权限矩阵、NSPanel 覆盖层、NSStatusItem 状态栏、自适应网格布局算法、多显示器坐标、排列完成时间性能验证、SPM 三 target 骨架可编译、SwiftLint 配置建立 |
| OUT | 完整功能实现、偏好设置窗口、应用专属配置、自定义布局模板、循环切换、跨 App 编排、权限引导窗口 UI、完整状态栏菜单交互、崩溃恢复持久化、Mac App Store 上架适配 |
| Exit Gate | 技术可行性已证明：兼容性矩阵 Tier A App 全部达标、骨架可编译、SwiftLint `--strict` 通过 |
| 决策产出 | 首批 ADR 倾向方案（依赖方向、激活模型、窗口范围、目标屏幕、还原语义、CGEventTap 生命周期、AXSetFrame 失败处理、偏好窗口技术选型、字母标签位置、Input Monitoring 权限必要性） |

P0 不交付面向终端用户的可用产品，只交付技术证据与项目骨架。P0 期间允许探索首批 ADR 主题，F1 验证后冻结。

### F0_权限引导

**战略目标**：首次启动时引导用户授予辅助功能权限，建立权限检测与引导流程。

| 维度 | 内容 |
|------|------|
| IN | 辅助功能权限检测（复用 P0 PermissionDetector）、权限引导窗口 UI（复用 Macim F0 设计）、Input Monitoring 权限引导（取决于 P0 探针结果） |
| OUT | 偏好设置、状态栏完整交互、窗口编排功能 |
| Exit Gate | 权限流程可用：未授权时显示引导、已授权时自动关闭、授权完成率可追踪 |
| 依赖 | P0 Exit Gate 通过 |

### F0.1_状态栏与快捷键

**战略目标**：建立状态栏交互和全局快捷键，让每个开发阶段都方便手动测试验收。

| 维度 | 内容 |
|------|------|
| IN | NSStatusItem 图标（简化状态：未授权/空闲/编排中）、下拉菜单（Trigger Tidy + 退出 + 权限项）、Carbon 热键 ⌘⌥T 可配置入口 |
| OUT | 4 种图标状态的完整交互、5 项菜单的完整交互、偏好设置窗口、热键录制器 |
| Exit Gate | 状态栏可交互、热键可触发回调 |
| 依赖 | F0 权限流程可用 |

### F1_窗口编排核心

**战略目标**：实现完整的"铺开 → 选择 → 还原"闭环，交付可验证的核心功能。

| 维度 | 内容 |
|------|------|
| IN | 窗口枚举、自适应网格布局、字母标签覆盖层（中心偏上动态约束）、字母选择输入、选中窗口临时放大、还原流程、AX 失败时原位置标签降级、Space 切换自动还原、App 切换不自动还原（Session 保留，返回后 working 继续）、目标 App 退出尽力恢复、超时还原 |
| OUT | 偏好设置窗口、应用专属配置、自定义布局模板、循环切换、跨 App 编排、跨屏聚合 |
| Exit Gate | 完整闭环可用：2～9 窗口排列 → 字母选择 → 临时放大 → 还原，核心恢复指标稳定 |
| 依赖 | F0 + F0.1 |

F1 内部按子功能切片（F1.0 Integration Baseline → F1.1 枚举 → F1.2 排列 → F1.3 标签与选择 → F1.4 最大化 → F1.5 还原 → F1.6 偏好设置），详见 [Tidy 窗口管理 App 功能列表](Tidy%20窗口管理%20App%20功能列表.md)。

### v0.1 内测（Pilot）

**战略目标**：验证目标用户是否反复使用核心闭环。

| 维度 | 内容 |
|------|------|
| IN | 15～30 名目标用户连续使用两周、量化指标收集（权限完成率 ≥ 70%、日均触发 ≥ 5 次、两周留存 ≥ 40%、还原成功率 ≥ 99%、P95 排列时间 ≤ 800ms、付费意愿 ≥ 20%） |
| OUT | 功能扩展、商业模式优化 |
| 决策 Gate | Go（高频使用完整闭环 → 进入 v1.0）/ Pivot（仅喜欢字母选择 → 转向轻量切换器）/ Stop（还原不可靠 → 暂停商业化先解决兼容性） |

### v1.0 正式版

**战略目标**：打磨权限、兼容性、日志、更新与购买体验，达到可公开销售水平。

| 维度 | 内容 |
|------|------|
| IN | v0.1 Pilot 通过、购买流程集成（14 天全功能试用 + 买断）、分发渠道（官网直售 + 公证签名 + 自动更新）、兼容性数据稳定 |
| OUT | 应用专属配置、自定义布局模板、循环切换、跨 App 编排 |

### F2_应用专属配置 / F3_自定义布局模板（v1.x）

**战略目标**：由 v0.1 验证中的真实高频需求排序决定优先级。

| 维度 | 内容 |
|------|------|
| IN | bundleIdentifier 匹配的应用级配置覆盖（F2）、用户保存与切换布局模板（F3） |
| Exit Gate | 应用级配置生效 / 模板可保存与切换 |
| 依赖 | F1 Exit Gate 通过 + v0.1 Pilot 通过 |

### F4_循环切换 / F5_跨App编排（v2.0+）

**战略目标**：仅在核心闭环已验证后投入。

| 维度 | 内容 |
|------|------|
| IN | working 阶段窗口循环切换（F4）、多 App 窗口同时编排（F5） |
| Exit Gate | 循环切换可用 / 跨 App 编排可用 |
| 依赖 | v1.0 正式版稳定运行 |

## 3. 阶段依赖关系

```text
P0_技术探针
  ↓ Exit Gate：技术可行性已证明，骨架可编译
F0_权限引导
  ↓ Exit Gate：权限流程可用
F0.1_状态栏与快捷键
  ↓ Exit Gate：状态栏可交互，热键可触发
F1_窗口编排核心
  ↓ Exit Gate：完整闭环可用
v0.1 内测（Pilot）
  ↓ Go / Pivot / Stop Gate
v1.0 正式版
  ↓
F2/F3（v1.x）→ F4/F5（v2.0+）
```

当前阶段：**P0_技术探针**（准备阶段，阶段文档草案状态）。

## 4. 兼容性验证 Tier

P0 期间按以下 Tier 组织兼容性验证：

| Tier | App | Gate 要求 |
|------|-----|-----------|
| A — Exit Gate | Xcode、VS Code / Electron、Finder、Safari、Chrome | 必须达到硬门槛（AX 成功率 ≥ 99%、排列时间 P95 ≤ 800ms） |
| B — Compatibility Evidence | JetBrains、Microsoft Office、Adobe | 必须测试、必须记录；允许 PASS / LIMITED / LABEL_ONLY / UNSUPPORTED，不阻塞 P0 Exit Gate |
