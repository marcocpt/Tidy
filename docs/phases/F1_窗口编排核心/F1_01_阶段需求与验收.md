# F1_窗口编排核心 阶段需求与验收

> 最后更新：2026-07-30 | 版本：v0.5
> 文档状态：草案
> 阶段定位：功能阶段（F1）；F0 + F0.1 Exit Gate 通过后开始

本文档是 F1_窗口编排核心 阶段的需求合同与验收依据。战略目标与边界以 [Tidy_开发路线图](../../Tidy_开发路线图.md) F1_窗口编排核心 为准；模块组织、状态机与 AX 行为细节参见 [Tidy 窗口管理 App 功能列表](../../Tidy%20窗口管理%20App%20功能列表.md)。

## 1. 目标（Goal）

F1_窗口编排核心 的目标是：

1. **完整闭环可用**：2～9 窗口排列 → 字母选择 → 临时放大 → 还原，核心流程在 Tier A App 上稳定工作；
2. **生产级健壮性**：AX 失败即终止 + 提示、selecting 阶段 Space 切换退出编排（working 阶段切 Space/App 保留 Session）、超时退出编排、目标 App 退出终止、working 阶段热键智能还原/重排；
3. **核心恢复指标稳定**：还原成功率 ≥ 99%、排列时间 P95 ≤ 800ms、还原时间 P95 ≤ 800ms。

P0 探针已实现核心闭环并验证可行性。F1 在此基础上补充生产级功能和健壮性。

## 4. 功能需求（FR）

### FR-F1-001 AX 失败即终止编排

- **描述**：arranging 阶段执行窗口移动操作时，任何窗口失败即立即终止本次编排，不回滚已排列窗口。
- **预期结果**：
  - 任何窗口移动操作失败 → 立即停止后续排列
  - 不回滚已成功排列的窗口（保留新位置）
  - 失败窗口保留在原位置
  - OverlayPanel 显示失败原因（窗口标题 + 错误码），2 秒后自动消失
  - 系统进入 idle 状态（窗口位置可能呈现半排列状态）
- **现有基础**：P0 已实现"跳过 + >50% 终止"策略，**需回退该策略并改为"任何失败即终止"**。
- **风险提示**：AX 失败在 Finder、系统设置、部分 Electron App 上不算罕见；本 FR 的严格策略会显著降低编排成功率，需在 F1 实现期实测失败率，若 >5% 重新评估本 FR。
- **实现细节**：具体 AX API 与失败检测方式在 F1_02 设计文档中定义。

### FR-F1-002 Space 切换退出编排

- **描述**：selecting 阶段，用户切换到其他 Space 时，触发编排退出（保留排列，进入 idle）。**working 阶段切 Space 不动作**（按 FR-F1-005 Session 保留）。
- **预期结果**：
  - selecting 阶段切 Space → 进入 idle，**窗口保留排列**（不还原到原始位置）
  - working 阶段切 Space → **不动作**（保持 working 状态，与切 App 行为一致）
  - **App 通知抑制（仅 selecting 阶段）**：若 selecting 阶段切 Space 时 200ms 内检测到 App 切换通知（macOS App 绑定 Space 场景），抑制 Space 退出，按 FR-F1-005 Session 保留处理
  - 抑制期间（200ms）完全忽略用户输入（热键、字母键）
- **实现方式**：监听系统 Space 切换通知 + App 切换通知，比较触发时序。具体通知 API 在 F1_02 设计文档中定义。

### FR-F1-003 超时退出编排

- **描述**：selecting 阶段 30 秒无输入时，自动退出编排。
- **预期结果**：
  - 进入 selecting 时启动 30 秒计时器
  - 用户按有效键时重置计时器
  - 超时后进入 idle，**窗口保留排列**（不还原到原始位置）
- **有效键定义**：a-z 字母键（映射到当前窗口标签）；其他键（含 ESC）不重置计时器，按各自语义处理。
- **配置**：超时时间默认 30 秒（F1.6 后可配置）。
- **不对称说明**：working 阶段无超时；用户主动退出由 FR-F1-008 working 热键承担。

### FR-F1-004 目标 App 退出终止编排

- **描述**：编排中目标 App 退出时，触发终止流程。
- **预期结果**：
  - 监听系统 App 终止通知
  - 退出的 App 标识 == 编排开始时记录的目标 App 标识时触发终止
  - **arranging 阶段退出**：按 FR-F1-001 处理（不回滚 + 提示 + idle）
  - **selecting 阶段退出**：进入 idle + 保留排列
  - **working 阶段退出**：取消放大 + 回 selecting（保留排列）；若原 App 已退出，回 selecting 等待用户操作
  - 终止失败时记录日志，不崩溃
- **实现细节**：具体 App 标识（PID / bundleIdentifier 等）在 F1_02 设计文档中定义。

### FR-F1-005 App 切换 / Space 切换 Session 保留

- **描述**：working 阶段用户切换到其他 App 或其他 Space 时，不退出编排；返回后继续 working 状态。selecting 阶段切 App 同样保留 Session。
- **预期结果**：
  - working 阶段切到其他 App → 保持 working 状态（不退出）
  - **working 阶段切到其他 Space → 保持 working 状态（不退出）**
  - 切回目标 App/Space → 仍在 working 状态
  - selecting 阶段切到其他 App → 保持 selecting 状态（不退出，受 FR-F1-002 抑制规则约束）
- **与 FR-F1-002 的关系**：selecting 阶段切 Space 默认退出编排，但若伴随 App 切换（200ms 内），按抑制规则保留 selecting。working 阶段切 Space 永远不退出。

### FR-F1-006 自适应布局规则

- **描述**：根据窗口数量采用不同的网格布局规则，确保窗口可读性与操作效率。
- **布局规则**：
  - **偶数窗口**：均匀平分为网格
    - 2 窗口 → 1 行 2 列（a|b）
    - 4 窗口 → 2 行 2 列（a|b / c|d）
    - 6 窗口 → 2 行 3 列（a|b|c / d|e|f）
    - 8 窗口 → 2 行 4 列
  - **奇数窗口 3/5/7**：第一个窗口 a 占左侧全高（相当于 2 格高度），剩余窗口在右侧 2 行网格
    - 3 窗口 → a 占左 1/2 + 右侧 2 行 1 列（a|b / a|c）
    - 5 窗口 → a 占左 1/3 + 右侧 2 行 2 列（a|b|c / a|d|e）
    - 7 窗口 → a 占左 1/4 + 右侧 2 行 3 列
  - **9 窗口特殊**：3 行 3 列均分（a|b|c / d|e|f / g|h|i），跳出 a 占左规则以保证 16:9 屏可读性
- **预期结果**：
  - 窗口按规则排列，标签按字母 a-z 从左到右、从上到下分配
  - 每个单元格内缩 8pt 作为窗口目标矩形
  - a 窗口在 3/5/7 奇数布局中占满左侧高度，突出主窗口地位；9 窗口例外
- **边界处理**：
  - 0 或 1 窗口：不触发热键编排（静默退出，不显示 OverlayPanel）
  - 10+ 窗口：截断到前 9 个窗口（按窗口枚举顺序），OverlayPanel 提示"仅排列前 9 个窗口"

### FR-F1-007 选择时序：先激活再放大

- **描述**：用户按字母选择窗口时，先激活目标窗口（前置），确认激活后再放大，让用户感知两步过程。
- **预期结果**：
  - 按字母 → 立即激活对应窗口（前置 + 模拟点击）
  - 激活后等待 250ms 让窗口前置生效
  - 250ms 后放大窗口到屏幕工作区（内缩 4pt）
  - 延迟期间忽略重复按键
  - **激活失败处理**：激活操作抛异常时不放大，记录日志，回 selecting 等待用户重新选择
- **配置说明**：250ms 为硬编码常量（F1.6 后可配置）；内缩 4pt 与排列的 8pt 不同，差异源于最大化时窗口已激活，需要更贴近屏幕边缘。
- **实现细节**：激活操作的具体 API 组合在 F1_02 设计文档中定义。

### FR-F1-008 working 阶段热键：窗口集合比较

- **描述**：working 阶段用户按热键时，比较当前前台 App 可见窗口集合与编排开始时记录的窗口集合，决定还原或重排。
- **预期结果**：
  - working 阶段按热键 → 重新枚举前台 App 可见窗口
  - **窗口集合完全相同** → 取消当前窗口放大 + 回 selecting（保留排列）
  - **窗口集合不同（窗口数或窗口标识变化）** → 触发重排，走完整 arranging → selecting 流程
  - 重排时清空旧的原位置快照，记录新的原位置快照
- **快照要求**：进入 arranging 时记录所有窗口的（窗口标识, 原始位置）快照；working 状态持久化此快照。
- **现有基础**：P0 编排器未实现 session 快照能力，需扩展。
- **实现细节**：窗口标识的具体形式（PID / AX window ID 等）在 F1_02 设计文档中定义。

## 6. 状态机（引用）

F1 阶段状态机扩展自 P0 探针，完整定义参见 [Tidy 窗口管理 App 功能列表](../../Tidy%20窗口管理%20App%20功能列表.md)（待补）。核心状态：

- **idle**：等待热键；窗口位置不固定（可能为原始位置或上次编排保留的排列）
- **arranging**：枚举窗口 + 记录快照 + 执行窗口排列
- **selecting**：显示标签 + 等待字母输入 + 30 秒计时
- **working**：当前窗口放大 + 等待热键/App 退出（切 Space 不退出）

状态转换摘要：

```
                              字母
                  热键        ↓                          热键(PID同)
idle ──────► arranging ──► selecting ──────────► working
 ▲              │             │                          │
 │              │ AX失败      │ 超时                     │ 热键(PID异)
 │              ▼             │ Space(无App抑制)         ▼
 │          [不回滚]          │ App退出              [重排 → arranging]
 │          +提示             ▼                       [取消放大 → selecting]
 │          +idle(半排列)   [进入 idle
 │                          +保留排列]
 │                                                       │
 │                                                       │ App退出
 │                                                       ▼
 │                                                  [取消放大 → selecting]
 │
 └─── 状态机不变量：working 切 Space 永远不退出（按 FR-F1-005 Session 保留）
```

## 7. 验收标准（AC）

### AC-F1-001 完整闭环可用

- **Given** 前台 App 有 2～9 个可见窗口；
- **When** 触发热键 → 字母选择 → 最大化 → 再次触发热键还原；
- **Then** 排列 → 选择 → 最大化 → 还原全流程正常工作；
- **覆盖**：P0 核心闭环回归。

### AC-F1-002 AX 失败即终止

- **Given** 排列时某窗口移动操作失败（测试 fixture：使用拒绝 AX 的 App 或锁定窗口）；
- **When** 检测到失败；
- **Then** 立即停止排列 + OverlayPanel 显示失败原因 + 进入 idle（已排列窗口保留新位置，失败窗口保留原位置）；
- **覆盖**：FR-F1-001。

### AC-F1-003 Space 切换退出编排

- **Given** selecting 阶段；
- **When** 用户切换到其他 Space（无伴随 App 切换）；
- **Then** 进入 idle + 保留排列；
- **覆盖**：FR-F1-002。

### AC-F1-003a working 阶段切 Space 不动作

- **Given** working 阶段；
- **When** 用户切换到其他 Space；
- **Then** 保持 working 状态（不退出、不取消放大、不回 selecting）；
- **覆盖**：FR-F1-005。

### AC-F1-004 超时退出编排

- **Given** selecting 阶段；
- **When** 30 秒无输入；
- **Then** 进入 idle + 保留排列；
- **覆盖**：FR-F1-003。

### AC-F1-005 目标 App 退出终止

- **Given** 编排中目标 App 退出；
- **When** 收到 App 终止通知；
- **Then**：
  - arranging 阶段 → 按 AC-F1-002 处理
  - selecting 阶段 → 进入 idle + 保留排列
  - working 阶段 → 取消放大 + 回 selecting
  - 终止失败时记录日志不崩溃；
- **覆盖**：FR-F1-004。

### AC-F1-006 App 切换 Session 保留

- **Given** working 或 selecting 阶段；
- **When** 切换到其他 App（无伴随 Space 切换）；
- **Then** 保持当前状态；切回后仍在原状态；
- **覆盖**：FR-F1-005。

### AC-F1-007 App + Space 同时切换的抑制

- **Given** selecting 阶段；
- **When** 切换到绑定其他 Space 的 App（200ms 内 App 通知 + Space 通知）；
- **Then** App 通知抑制 Space 退出，保持 selecting 状态；抑制期间忽略用户输入；
- **覆盖**：FR-F1-002 + FR-F1-005。

### AC-F1-007a working 阶段 App + Space 同时切换

- **Given** working 阶段；
- **When** 切换到绑定其他 Space 的 App；
- **Then** 保持 working 状态（切 Space 本就不动作，切 App 按 Session 保留）；
- **覆盖**：FR-F1-005。

### AC-F1-008 自适应布局规则

- **Given** 前台 App 有 2～9 个可见窗口；
- **When** 触发热键进入编排；
- **Then** 窗口按 FR-F1-006 规则排列：
  - 偶数窗口均匀平分网格
  - 奇数窗口 3/5/7：a 占左侧全高，剩余窗口在右侧 2 行网格
  - 9 窗口：3 行 3 列均分
  - 标签按字母 a-z 从左到右、从上到下分配；
- **覆盖**：FR-F1-006。

### AC-F1-009 选择时序：先激活再放大

- **Given** selecting 阶段，用户按字母选择窗口；
- **When** 拦截到有效按键；
- **Then** 先激活目标窗口（前置 + 模拟点击），等待 250ms 后再放大；激活失败时不放大、回 selecting；
- **覆盖**：FR-F1-007。

### AC-F1-010 working 热键窗口集合比较

- **Given** working 阶段；
- **When** 用户按热键；
- **Then**：
  - 窗口集合完全相同 → 取消放大 + 回 selecting（保留排列）
  - 窗口集合不同 → 触发重排（arranging → selecting）
- **覆盖**：FR-F1-008。

### AC-F1-011 边界窗口数处理

- **Given** 前台 App 有 0/1/10+ 可见窗口；
- **When** 触发热键；
- **Then**：
  - 0 或 1 窗口 → 静默退出，不显示 OverlayPanel
  - 10+ 窗口 → 截断到前 9 个 + OverlayPanel 提示；
- **覆盖**：FR-F1-006 边界处理。

### AC-F1-012 Exit Gate 通过

- **Given** AC-F1-001 至 AC-F1-011 + AC-F1-003a/007a 全部通过；
- **Then** F1 Exit Gate 通过，完整闭环可用，允许进入 v0.1 Pilot；
- **覆盖**：全部 FR 与 NFR。

## 8. 约束（Constraints）

### 8.1 平台约束

- 目标平台：macOS 12（Monterey）及以上
- 系统可访问性接口行为受 App 实现影响：Finder、系统设置、部分 Electron App 行为不稳定
- 多显示器：当前阶段假设编排发生在触发热键时鼠标所在屏；多屏独立 Space 行为未覆盖（FR-F1-002 仅处理单 Space 切换）

### 8.2 UI 约束

- 不新增独立弹窗组件；所有提示通过 OverlayPanel 显示
- OverlayPanel 容量限制：最多 9 个字母标签
- 250ms 激活等待为硬编码常量，F1.6 后才可配置

### 8.3 实现约束

- P0 已实现的">50% 终止"策略需回退
- P0 编排器需扩展 session 快照能力（窗口标识 + frame 快照）
- App 通知抑制窗 200ms 为经验值，需在 F1 实现期加入日志验证时序

### 8.4 性能约束

- 窗口移动操作为主开销；9 窗口排列需 9 次移动操作，单次失败即终止
- 还原 = N 次窗口移动操作（N = 已排列窗口数）；与排列对称

## 9. 决策自由度（Decision Freedom）

实现层可自由决定的细节，无需在本阶段固定：

- **计时器实现选型**：系统级计时器 / async 任务等
- **监听注册时机**：AppDelegate 启动时 / 首次进入编排时
- **窗口标识存储位置**：编排器内部字段 / 独立 SessionStore
- **OverlayPanel 提示样式**：文字颜色、消失动画、位置（顶部/底部）
- **App 通知抑制实现**：合并通知监听 + 时序比较 / 通知到达后延时 200ms 决策
- **重排时是否复用 OverlayPanel**：是 / 重新创建
- **250ms 是否拆分为可调常量**：F1 内为硬编码，F1.6 后可配置
