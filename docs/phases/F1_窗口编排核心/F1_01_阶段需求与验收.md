# F1_窗口编排核心 阶段需求与验收

> 最后更新：2026-07-30 | 版本：v0.12
> 文档状态：草案
> 阶段定位：功能阶段（F1）；F0 + F0.1 Exit Gate 通过后开始

本文档是 F1_窗口编排核心 阶段的需求合同与验收依据。战略目标与边界以 [Tidy_开发路线图](../../Tidy_开发路线图.md) F1_窗口编排核心 为准；模块组织、状态机与 AX 行为细节参见 [Tidy 窗口管理 App 功能列表](../../Tidy%20窗口管理%20App%20功能列表.md)。

## 1. 目标（Goal）

F1_窗口编排核心 的目标是：

1. **完整闭环可用**：2～9 窗口排列 → 字母选择 → 临时放大 → 再次热键回 selecting（Session Navigator 模型），核心流程在 Tier A App 上稳定工作；
2. **生产级健壮性**：AX 失败即终止 + 提示、selecting 阶段切 Space/App 退出编排、超时退出编排、目标 App 退出终止编排（arranging/selecting/working 三阶段均退出）、working 阶段切 Space/App 保留 Session；
3. **核心恢复指标稳定**：性能指标（排列时间、还原时间、还原成功率）展缓到 F1 实现期确定，基于 P0 探针实测基线设定门槛。

P0 探针已实现核心闭环并验证可行性。F1 在此基础上补充生产级功能和健壮性。

## 4. 功能需求（FR）

### 4.1 编排与布局

#### FR-F1-001 编排触发与窗口范围

- **触发**：用户按下 Tidy 热键
- **目标 App**：触发热键时的前台 App
- **窗口范围**：目标 App 的所有可见窗口
- **目标屏幕**：触发热键时焦点窗口所在屏
- **窗口数量**：2～9 个；0/1/10+ 按边界处理

#### FR-F1-002 自适应布局规则

Tidy 应根据参与编排的窗口数量生成确定性布局：

| N | 布局 |
|---|------|
| 2 | 1 行 2 列（a\|b） |
| 3 | a 占左 1/2 全高 + 右侧 2 行 1 列（a\|b / a\|c） |
| 4 | 2 行 2 列（a\|b / c\|d） |
| 5 | a 占左 1/3 全高 + 右侧 2 行 2 列（a\|b\|c / a\|d\|e） |
| 6 | 2 行 3 列（a\|b\|c / d\|e\|f） |
| 7 | a 占左 1/4 全高 + 右侧 2 行 3 列 |
| 8 | 2 行 4 列 |
| 9 | 3 行 3 列均分（跳出 a 占左规则以保证 16:9 屏可读性） |

**布局规则**：

- a 标签分配给 z-order 最前窗口（最后被聚焦过的窗口）
- 剩余窗口按 z-order 降序分配 b/c/d... 标签
- 标签顺序按字母 a-z 从左到右、从上到下分配
- 排列区域占满目标屏幕可用工作区（macOS 屏幕工作区，已扣除菜单栏与 Dock）
- 窗口间无空隙，窗口边缘贴合工作区边界
- 3/5/7 奇数布局中 a 窗口占满左侧高度，突出主窗口地位；9 窗口例外

**边界处理**：

- 0 或 1 窗口：不触发热键编排（静默退出，不显示覆盖层）
- 10+ 窗口：截断到前 9 个窗口（按 z-order 降序），覆盖层提示"仅排列前 9 个窗口"

### 4.2 选择与临时工作

#### FR-F1-003 选择时序：先激活再放大

用户按字母选择窗口时，应先激活目标窗口（前置），确认激活后再放大，让用户感知两步过程：

- 按字母 → 立即激活对应窗口（前置 + 模拟点击）
- 激活后等待 250ms 让窗口前置生效
- 250ms 后放大窗口到目标屏幕工作区（占满可用工作区）
- 250ms 延迟期间忽略后续按键（含同一字母与其他字母）
- **激活失败处理**：激活操作抛异常时不放大；覆盖层显示失败原因（窗口标题 + 错误码）2 秒后自动消失；回 selecting 等待用户重新选择；记录日志

250ms 为视觉过渡时长（F1.6 后可调整）。

### 4.3 Session 生命周期与事件矩阵

#### FR-F1-004 状态×事件矩阵

下表是 Session 生命周期的**唯一行为真值**，其他章节不再描述另一套：

| 事件 | arranging | selecting | working |
|------|----------|-----------|---------|
| Tidy 热键 | — | — | 集合同 → 取消放大 + 回 selecting（保留排列）；集合异 → 触发重排（清空旧快照） |
| 切到其他 App | 不适用 | → idle + 保留排列 | 保留 Session（保持 working，不动作） |
| 切到其他 Space | 不适用 | → idle + 保留排列 | 保留 Session（保持 working，不动作） |
| Timeout (30s) | — | → idle + 保留排列 | — |
| Esc | 忽略 | → idle + 保留排列 | 忽略 |
| 目标 App 退出 | → 按 AX 失败处理（不回滚 + 提示 + idle） | → idle + 保留排列 | → idle |
| AX 失败 | → 不回滚 + 提示 + idle | — | — |
| 有效字母键 | — | → 激活 + 放大 → working | — |

**Session 语义**：

- 进入 arranging 时记录所有窗口的（窗口标识, 原始位置）快照
- Tidy 修改后的窗口位置成为新的"原始位置"基线，不需要恢复到更早状态
- working 阶段切到其他 App/Space 后按热键启动新编排时，旧 Session 的快照可被新编排覆盖（用户接受数据丢失，因为新基线语义）
- 任一时刻最多存在一个活动 Tidy Session

#### FR-F1-005 working 阶段热键：窗口集合比较

working 阶段用户按热键时：

- 重新枚举前台 App 可见窗口
- **窗口集合完全相同**（窗口数与窗口标识均不变） → 取消当前窗口放大 + 回 selecting（保留排列）
- **窗口集合不同** → 触发重排，走完整 arranging → selecting 流程；重排时清空旧快照，记录新快照

### 4.4 AX 失败与异常处理

#### FR-F1-006 AX 失败即终止编排

arranging 阶段执行窗口移动操作时，任何窗口失败即立即终止本次编排：

- 任何窗口移动操作失败 → 立即停止后续排列
- 不回滚已成功排列的窗口（保留新位置）
- 失败窗口保留在原位置
- 覆盖层显示失败原因（窗口标题 + 错误码）2 秒后自动消失
- 系统进入 idle 状态（窗口位置可能呈现半排列状态）
- 终止失败时记录日志，不崩溃

**现有基础**：P0 已实现"跳过 + >50% 终止"策略，**需回退该策略并改为"任何失败即终止"**。

**风险提示**：AX 失败在 Finder、系统设置、部分 Electron App 上不算罕见；本 FR 的严格策略会显著降低编排成功率，需在 F1 实现期实测失败率，若 >5% 重新评估本 FR。

### 4.5 用户可见错误

所有错误通过编排覆盖层显示，不新增独立弹窗组件：

- **错误内容**：窗口标题 + 错误码
- **显示时长**：2 秒后自动消失
- **覆盖场景**：AX 失败（FR-F1-006）、激活失败（FR-F1-003）、10+ 窗口截断提示（FR-F1-002）

## 5. 非功能需求（NFR）

### 5.1 性能（展缓确定）

**性能指标展缓到 F1 实现期确定**。F1 实现期将基于 P0 探针实测基线设定以下指标门槛：

- 排列完成时间 P95（2 / 5 / 9 窗口场景）
- 还原时间 P95（working → idle）
- 还原成功率

展缓原因：F1 新增的健壮性功能（Space/App 切换监听、App 退出监听、超时计时器、session 快照）会引入运行时开销，需实测后才能确定合理门槛。提前设定数值可能导致 AC 不可执行或过度保守。

### 5.2 可靠性

- AX 失败不崩溃
- Space 切换、App 退出、超时等边界场景安全退出编排
- 状态机非法转换记录 Error 日志

### 5.3 兼容性（Tier A）

完整闭环必须在批准的 Tier A App 集上完成兼容性回归。具体 App × N 矩阵在 F1_03 测试用例表展开。

## 6. 状态机（引用）

F1 阶段状态机扩展自 P0 探针，完整定义参见 [Tidy 窗口管理 App 功能列表](../../Tidy%20窗口管理%20App%20功能列表.md)（待补）。核心状态：

- **idle**：等待热键；窗口位置不固定（可能为原始位置或上次编排保留的排列，新基线语义）
- **arranging**：枚举窗口 + 记录快照 + 执行窗口排列
- **selecting**：显示标签 + 等待字母输入 + 30 秒计时
- **working**：当前窗口放大 + 等待热键（切 Space/App 保留 Session；目标 App 退出 → idle）

状态转换摘要：

```
                              字母
                  热键        ↓                          热键(集合同)
idle ──────► arranging ──► selecting ──────────► working
 ▲              │             │                          │
 │              │ AX失败      │ 超时                     │ 热键(集合异)
 │              ▼             │ Space/App切换             ▼
 │          [不回滚]          │ Esc                      [重排 → arranging]
 │          +提示             │ App退出              [取消放大 → selecting]
 │          +idle(半排列)   ▼
 │                          [进入 idle
 │                           +保留排列]
 │                                                       │
 │                                                       │ App退出
 │                                                       ▼
 │                                                  [进入 idle]
 │
 └─── 状态机不变量：working 阶段切 Space/App 不动作（保留 Session）；
      目标 App 退出 → idle（放弃 working，不恢复已不存在窗口）
```

## 7. 验收标准（AC）

### AC-F1-001 核心闭环

- **覆盖**：FR-F1-001 / FR-F1-002 / FR-F1-003 / FR-F1-004 / FR-F1-005
- **Given** Tier A App 有 2 / 5 / 9 个可见窗口；
- **When** 触发热键 → 字母选择 → 临时放大 → 再次触发热键；
- **Then** arranging → selecting → working → 回 selecting（窗口集合相同分支）全流程正常工作；
- **最终窗口位置**：保留在 Tidy 修改后的位置（新基线）。

### AC-F1-002 布局规则成立

- **覆盖**：FR-F1-002
- **Given** N = 2…9 的可见窗口；
- **Then**：
  - 实际布局与 FR-F1-002 表格一致
  - 任意两个目标窗口无重叠
  - 所有目标区域位于目标屏幕工作区内
  - a 标签分配给 z-order 最前窗口，剩余按 z-order 降序

### AC-F1-003 边界窗口数

- **覆盖**：FR-F1-002 边界处理
- **Given** 前台 App 有 0 / 1 / 10+ 可见窗口；
- **When** 触发热键；
- **Then**：
  - 0 或 1 窗口 → 静默退出，不显示覆盖层
  - 10+ 窗口 → 截断到前 9 个 + 覆盖层提示

### AC-F1-004 selecting 生命周期

- **覆盖**：FR-F1-004
- **Given** selecting 阶段；
- **When** 触发 timeout / Esc / 切到其他 App / 切到其他 Space；
- **Then** 均进入 idle + 保留排列。

### AC-F1-005 working 生命周期

- **覆盖**：FR-F1-004 / FR-F1-005
- **Given** working 阶段；
- **When** 切到其他 App 或其他 Space；
- **Then** 保持 working 状态（保留 Session）；
- **When** 按 Tidy 热键；
- **Then**：
  - 窗口集合完全相同 → 取消放大 + 回 selecting（保留排列）
  - 窗口集合不同 → 触发重排（arranging → selecting）

### AC-F1-006 异常恢复

- **覆盖**：FR-F1-006 / FR-F1-003 激活失败
- **Given** arranging 阶段某窗口移动失败 / selecting 阶段激活失败；
- **Then**：
  - arranging 失败 → 立即停止 + 覆盖层提示失败原因 2 秒 + 进入 idle（已排列窗口保留新位置，失败窗口保留原位置）
  - 激活失败 → 不放大 + 覆盖层提示失败原因 2 秒 + 回 selecting

### AC-F1-007 目标 App 退出

- **覆盖**：FR-F1-004
- **Given** 编排中目标 App 退出；
- **Then**：
  - arranging 阶段 → 按 AC-F1-006 处理
  - selecting 阶段 → 进入 idle + 保留排列
  - working 阶段 → 进入 idle（放弃 working，不恢复已不存在窗口）
  - 终止失败时记录日志不崩溃

### AC-F1-008 Tier A 兼容性

- **覆盖**：NFR 5.3
- **Given** 批准的 Tier A App 集；
- **Then** 完整闭环在所有 Tier A App 上通过兼容性回归；结果满足 NFR-F1-xxx（实现期确定）。

## 8. Exit Gate

F1 Exit Gate = PASS 当且仅当：

1. 所有 Must AC（AC-F1-001 至 AC-F1-008）PASS；
2. 所有 NFR 门槛 PASS（性能门槛在 F1 编码开始后基于 P0 baseline 确定）；
3. Tier A compatibility gate PASS；
4. 无 Blocker / Critical known defect；
5. F1_03 测试用例表 AC coverage 无 MISSING；
6. 允许进入 v0.1 Pilot。

## 9. 约束（Constraints）

### 9.1 平台约束

- 目标平台：macOS 12（Monterey）及以上
- 系统可访问性接口行为受 App 实现影响：Finder、系统设置、部分 Electron App 行为不稳定
- 多显示器：编排发生在触发热键时焦点窗口所在屏；多屏独立 Space 行为未覆盖

### 9.2 UI 约束

- 不新增独立弹窗组件；所有提示通过编排覆盖层显示
- 覆盖层容量限制：最多 9 个字母标签

### 9.3 实现约束

- P0 已实现的">50% 终止"策略需回退
- P0 编排器需扩展 session 快照能力（窗口标识 + 原始位置快照）

### 9.4 性能约束

- 窗口移动操作为主开销；9 窗口排列需 9 次移动操作，单次失败即终止
- 取消放大 = 1 次窗口移动操作；与排列不对称（排列 N 次，取消放大 1 次）

## 10. 决策自由度（Decision Freedom）

实现层可自由决定的细节，无需在本阶段固定：

- 计时器实现选型：系统级计时器 / async 任务等
- 监听注册时机：AppDelegate 启动时 / 首次进入编排时
- 窗口标识存储位置：编排器内部字段 / 独立 SessionStore
- 覆盖层提示样式：文字颜色、消失动画、位置（顶部/底部）
- 重排时是否复用覆盖层：是 / 重新创建
- 250ms 是否拆分为可调常量：F1 内固定值，F1.6 后可调整
