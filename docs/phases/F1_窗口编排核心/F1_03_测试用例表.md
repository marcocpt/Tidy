# F1_窗口编排核心 测试用例表

> 最后更新：2026-07-30 | 版本：v0.1
> 文档状态：草案
> 阶段定位：功能阶段（F1）；对应 [F1_01_阶段需求与验收](F1_01_阶段需求与验收.md) 与 [F1_02_设计文档](F1_02_设计文档.md)

## 1. 概述

本文档定义 F1 阶段所有验收标准（AC-F1-001 ~ AC-F1-008）的测试用例，覆盖单元测试、UI 测试与手动测试三类。

### 1.1 测试位置策略

| 类型 | 框架 | 执行位置 | 覆盖范围 |
|------|------|---------|---------|
| 单元测试 | XCTest | 本地 + CI | TidyCore 纯逻辑（布局算法、状态机、Session 快照、窗口集合比较） |
| UI 测试 | XCUITest | **仅 CI** | 端到端核心闭环、覆盖层可见性、热键触发 |
| 手动测试 | 人工 | 本地 | AX 真实行为、Space/App 切换、App 退出、Tier A 兼容性、性能基线 |

**本地禁止执行 XCUITest**（用户偏好）：UI 测试只在 CI 上执行，本地仅执行 XCTest 与编译检查。

### 1.2 Tier A App 集

| App | 代表类型 | 备注 |
|-----|---------|------|
| Xcode | 原生 macOS | Tier A 必测 |
| VS Code | Electron | Tier A 必测，AX 行为可能不稳定 |
| Finder | 系统应用 | Tier A 必测，AX 行为可能不稳定 |
| Safari | 原生 macOS | Tier A 必测 |
| Chrome | 多进程 | Tier A 必测 |

### 1.3 N 矩阵

每个 AC 的 N 取值：2 / 5 / 9（覆盖偶数、奇数分割、9 窗口例外三类布局）。

## 2. AC-F1-001 核心闭环

**覆盖**：FR-F1-001 / FR-F1-002 / FR-F1-003 / FR-F1-004 / FR-F1-005

### TC-F1-001-01 核心闭环端到端（手动 + UI）

| 项 | 内容 |
|---|------|
| Given | Tier A App（Xcode）有 5 个可见窗口 |
| When | 触发热键 → 等待 arranging 完成 → 按字母 c → 等待 250ms 放大 → 再次触发热键 |
| Then | arranging → selecting → working → 回 selecting（窗口集合相同分支）全流程正常工作 |
| 最终窗口位置 | 保留在 Tidy 修改后的位置（新基线） |
| 证据 | 录屏 + os_log 性能埋点 |
| 位置 | 手动本地 + XCUITest CI |

### TC-F1-001-02 核心闭环 N=2/9（手动）

| 项 | 内容 |
|---|------|
| Given | Tier A App 分别有 2 / 9 个可见窗口 |
| When | 重复 TC-F1-001-01 流程 |
| Then | 全流程正常工作 |
| 位置 | 手动本地 |

### TC-F1-001-03 状态机转换单元测试（XCTest）

## 11. 测试基础设施需求

### 11.1 单元测试 mock 需求

- `MockWindowEnumerating`：返回预设窗口列表，支持 z-order 排序
- `MockWindowManipulating`：记录所有调用（setFrame / activateWindow / snapshot / restore），支持按窗口 ID 配置失败返回值
- `MockGridLayoutCalculating`：返回预设 LayoutCell 列表
- `MockEventTapManaging`：记录 startTap / stopTap 调用，支持手动触发回调
- `MockOverlayShowing`：记录 showOverlay / hideOverlay / showError 调用
- `MockScreenInfoProviding`：返回预设 ScreenInfo
- `MockSystemNotificationObserver`：模拟 NSWorkspace 通知（Space 切换 / App 切换 / App 退出）

### 11.2 CI 流水线需求

- macOS runner（macOS 12+）
- Xcode 14.1+
- 辅助功能权限预配置（CI runner 需要 granting accessibility to XCUITest runner）
- SwiftLint `--strict` 门禁
- 性能基线报告产物上传

### 11.3 手动测试脚本

- `scripts/measure-performance.sh`：批量触发热键 + 收集 os_log 性能埋点（P0 已存在）
- 手动测试清单：每 Tier A App × N 组合的逐步操作指南（在 F1_04 实现计划中展开）
