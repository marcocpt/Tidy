## 1. 概述

F1 在 P0 探针核心闭环基础上补充生产级健壮性与自定义布局规则。本文档描述布局算法、选择时序、健壮性机制的设计。

## 2. 自适应布局算法（FR-F1-006）

### 2.1 布局规则

根据窗口数量分为两类布局：

#### 偶数窗口：标准网格

均匀划分行列，标签按字母 a-z 从左到右、从上到下分配。

| 窗口数 | 行 × 列 | 布局示意 |
|--------|---------|---------|
| 2 | 1 × 2 | `a|b` |
| 4 | 2 × 2 | `a|b / c|d` |
| 6 | 2 × 3 | `a|b|c / d|e|f` |
| 8 | 2 × 4 | `a|b|c|d / e|f|g|h` |
| 10+ | 接近正方形 | `ceil(sqrt(n))` 列 |

#### 奇数窗口 ≥3：分割布局

第一个窗口 a 占左侧全高（相当于 2 格高度），剩余窗口在右侧 2 行网格。

| 窗口数 | a 占比 | 右侧网格 | 布局示意 |
|--------|--------|---------|---------|
| 3 | 左 1/2 | 2 行 1 列 | `a|b / a|c` |
| 5 | 左 1/3 | 2 行 2 列 | `a|b|c / a|d|e` |
| 7 | 左 1/4 | 2 行 3 列 | `a|b|c|d / a|e|f|g` |
| 9 | 左 1/5 | 2 行 4 列 | `a|b|c|d|e / a|f|g|h|i` |

### 2.2 设计原理

- **偶数平分**：窗口数能均匀划分行列，无空格，视觉平衡
- **奇数 a 占全高**：奇数窗口无法均匀平分，让 a 突出主窗口地位，剩余窗口在右侧紧凑排列
- **右侧固定 2 行**：避免右侧窗口过窄，保证可读性

### 2.3 单元格内缩

每个窗口目标矩形从单元格内缩 8pt，避免窗口紧贴边界。

### 2.4 最大化时序（FR-F1-007）

选择窗口时采用"先激活再放大"两步时序：

1. **激活阶段**（立即）：
   - AX 组合调用：`AXMainWindow` + `AXFocusedWindow` + `AXFrontmost` + `AXFocused`
   - CGEvent 模拟点击窗口中心（AX 失败时强制前置）
2. **等待阶段**（250ms）：让系统处理窗口前置
3. **放大阶段**：`setFrame` 到屏幕工作区（内缩 4pt）

## 3. 健壮性机制

### 3.1 AX 失败降级（FR-F1-001）

- 排列时个别窗口 `AXSetFrame` 失败 → 保留原位置 + 显示标签
- 失败数 > 半数 → 终止编排，还原已排列窗口

### 3.2 Space 切换自动还原（FR-F1-002）

- 监听 `NSWorkspace.activeSpaceDidChangeNotification`
- selecting/working 阶段切 Space → 触发 `deactivate()` 还原

### 3.3 超时还原（FR-F1-003）

- 进入 selecting 时启动 30 秒计时器
- 有效按键重置计时器
- 超时触发 `deactivate()` 还原

### 3.4 App 退出恢复（FR-F1-004）

- 监听 `NSWorkspace.didTerminateApplicationNotification`
- 退出 App PID == frontmostPID → 触发还原

### 3.5 Session 保留（FR-F1-005）

- working 阶段切其他 App → 不还原，保持 working 状态
- 与 Space 切换不同：App 切换不改变 Space，窗口仍可见

## 4. 模块交互

### 4.1 selectWindow 时序

```
按字母 → 停 EventTap → activateWindow(AX+CGEvent)
  → 等待 250ms → setFrame 最大化 → hideOverlay → state=working
  → onStateChange 回调 → activateFrontmostApp(NSWorkspace)
```

### 4.2 isSelectingWindow 标志位

- 防止 250ms 延迟期间重复触发 selectWindow
- deactivate() 时重置为 false
