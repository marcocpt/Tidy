# F1_窗口编排核心 设计文档

## 1. 概述

F1 在 P0 探针核心闭环基础上补充生产级健壮性与自适应布局规则。本文档描述布局算法、选择时序、Session 生命周期、状态×事件矩阵、健壮性机制的设计。

本文档是 F1_01 需求文档的实现层设计，行为约束以 F1_01 为唯一真值。本文档不重复 F1_01 已定义的 FR 全文，只展开设计决策与模块交互。

## 2. 自适应布局算法（FR-F1-002）

### 2.1 布局规则

根据窗口数量 N（2 ≤ N ≤ 9）分两类布局。窗口区域占满目标屏幕可用工作区（macOS 屏幕工作区，已扣除菜单栏与 Dock），窗口间无空隙，窗口边缘贴合工作区边界。

#### 偶数窗口：标准网格

均匀划分行列，标签按字母 a-z 从左到右、从上到下分配。

| N | 行 × 列 | 布局示意 |
|---|---------|---------|
| 2 | 1 × 2 | `a\|b` |
| 4 | 2 × 2 | `a\|b / c\|d` |
| 6 | 2 × 3 | `a\|b\|c / d\|e\|f` |
| 8 | 2 × 4 | `a\|b\|c\|d / e\|f\|g\|h` |

#### 奇数窗口 3/5/7：分割布局

第一个窗口 a 占左侧全高（占满左侧 1/2、1/3、1/4 宽度），剩余窗口在右侧 2 行网格。

| N | a 占比 | 右侧网格 | 布局示意 |
|---|--------|---------|---------|
| 3 | 左 1/2 | 2 行 1 列 | `a\|b / a\|c` |
| 5 | 左 1/3 | 2 行 2 列 | `a\|b\|c / a\|d\|e` |
| 7 | 左 1/4 | 2 行 3 列 | `a\|b\|c\|d / a\|e\|f\|g` |

#### 9 窗口：3×3 均分例外

9 窗口跳出"a 占左"规则，采用 3 行 3 列均分布局，保证 16:9 屏可读性。

| N | 行 × 列 | 布局示意 |
|---|---------|---------|
| 9 | 3 × 3 | `a\|b\|c / d\|e\|f / g\|h\|i` |

### 2.2 a 标签分配规则

- a 标签分配给 z-order 最前窗口（最后被聚焦过的窗口）
- 剩余窗口按 z-order 降序分配 b/c/d... 标签
- 标签顺序按字母 a-z 从左到右、从上到下分配

### 2.3 边界处理

| 窗口数 | 行为 |
|--------|------|
| 0 或 1 | 不触发热键编排（静默退出，不显示覆盖层） |
| 2 ~ 9 | 按上述布局规则排列 |
| 10+ | 截断到前 9 个窗口（按 z-order 降序），覆盖层提示"仅排列前 9 个窗口" |

### 2.4 设计原理

- **偶数平分**：窗口数能均匀划分行列，无空格，视觉平衡
- **奇数 a 占全高**：奇数窗口无法均匀平分，让 a 突出主窗口地位，剩余窗口在右侧紧凑排列
- **9 窗口例外**：3×3 均分在 16:9 屏上每格接近 16:9 子区域，可读性优于 a 占左 1/5 + 右侧 2×4（右侧每格过窄）
- **无内缩**：占满可用工作区，最大化屏幕利用率；窗口边缘贴合工作区边界由 AXSetFrame 直接写入

## 3. 选择时序（FR-F1-003）

### 3.1 先激活再放大两步时序

用户按字母选择窗口时，采用"先激活再放大"两步时序，让用户感知两步过程：

1. **激活阶段**（立即）：
   - 通过系统可访问性接口设置窗口为 App 主窗口并聚焦
   - 通过模拟点击窗口中心强制系统前置窗口（AX 调用可能返回 success 但不改变 z-order）
2. **等待阶段**（250ms）：让系统处理窗口前置
3. **放大阶段**：将窗口移动到目标屏幕可用工作区（占满，无内缩）

### 3.2 按键忽略窗口

250ms 延迟期间忽略后续按键（含同一字母与其他字母），防止重复触发选择流程。实现层通过 `isSelectingWindow` 标志位在激活阶段置位，放大阶段 defer 重置。

### 3.3 激活失败处理

激活操作抛异常时：

- **不放大**：跳过放大阶段
- **覆盖层提示**：显示失败原因（窗口标题 + 错误码）2 秒后自动消失
- **回 selecting**：保持 selecting 状态，等待用户重新选择
- **记录日志**：Error 级日志

### 3.4 250ms 常量

250ms 为视觉过渡时长，F1 内固定值，F1.6（偏好设置）后可调整。本阶段不拆分为可调常量。

## 4. Session 生命周期与状态×事件矩阵（FR-F1-004）

### 4.1 状态×事件矩阵

下表是 Session 生命周期的**唯一行为真值**，其他章节不再描述另一套：

| 事件 | arranging | selecting | working |
|------|----------|-----------|---------|
| Tidy 热键 | — | — | 集合同 → 取消放大 + 回 selecting（保留排列）；集合异 → 触发重排（清空旧快照） |
| 切到其他 App | 不适用 | → idle + 保留排列 | 保留 Session（保持 working，不动作） |
| 切到其他 Space | 不适用 | → idle + 保留排列 | 保留 Session（保持 working，不动作） |
| Timeout (30s) | — | → idle + 保留排列 | — |
| Esc | 忽略 | → idle + 保留排列 | 忽略 |
| 目标 App 退出 | → 按 AX 失败处理（不回滚 + 提示 + idle） | → idle + 保留排列 | → idle |
| AX 失败 | → 不回滚 + 提示 + idle | — | — |
| 有效字母键 | — | → 激活 + 放大 → working | — |

### 4.2 Session 快照语义

- 进入 arranging 时记录所有窗口的（窗口标识, 原始位置）快照
- Tidy 修改后的窗口位置成为新的"原始位置"基线，不需要恢复到更早状态
- working 阶段切到其他 App/Space 后按热键启动新编排时，旧 Session 的快照可被新编排覆盖（用户接受数据丢失，因为新基线语义）
- 任一时刻最多存在一个活动 Tidy Session

### 4.3 三阶段退出语义

#### selecting 阶段退出（切 App / 切 Space / Timeout / Esc / 目标 App 退出）

- 进入 idle
- 保留排列（已排列窗口位置不变，新基线语义）
- 隐藏覆盖层
- 停止 EventTap 与超时计时器
- 不清空 Session 快照（用户可在 working 阶段返回）

#### working 阶段退出（仅目标 App 退出）

- 进入 idle
- 放弃 working（不恢复已不存在窗口）
- 不清空 Session 快照（语义上 Session 已失效，但内存清理可延迟）

#### working 阶段不动作（切 App / 切 Space）

- 保持 working 状态
- 不触发任何窗口操作
- Session 保留（用户切回后可继续按热键触发集合比较）

### 4.4 状态机不变量

```
                              字母
                  热键        ↓                          热键(集合同)
idle ──────► arranging ──► selecting ──────────► working
 ▲              │             │                          │
 │              │ AX失败      │ 超时                     │ 热键(集合异)
 │              ▼             │ Space/App切换             ▼
 │          [不回滚]          │ Esc                      [重排 → arranging]
 │          +提示             │ App退出              [取消放大 → selecting]
 │          +idle(半排列)   ▼
 │                          [进入 idle
 │                           +保留排列]
 │                                                       │
 │                                                       │ App退出
 │                                                       ▼
 │                                                  [进入 idle]
 │
 └─── 状态机不变量：working 阶段切 Space/App 不动作（保留 Session）；
      目标 App 退出 → idle（放弃 working，不恢复已不存在窗口）
```

## 5. working 阶段热键：窗口集合比较（FR-F1-005）

### 5.1 触发流程

working 阶段用户按 Tidy 热键时：

1. 重新枚举前台 App 可见窗口
2. 与 Session 快照中的窗口集合比较（窗口数与窗口标识均不变即视为相同）
3. 根据比较结果分支处理

### 5.2 集合相同分支

- 取消当前窗口放大（将放大窗口恢复到 arranging 阶段排列的位置）
- 回 selecting（保留排列）
- 显示覆盖层（与 arranging → selecting 时一致）
- 启动 selecting 超时计时器与 EventTap

### 5.3 集合不同分支

- 触发重排，走完整 arranging → selecting 流程
- 重排时清空旧 Session 快照
- 记录新 Session 快照（新窗口集合的原始位置）

### 5.4 窗口标识选择

窗口标识采用 CGWindowID（CGWindowList 创建时分配的系统级唯一标识）。PID 不适用（同一 App 多窗口 PID 相同），bundleIdentifier 不适用（同 App 多窗口无法区分）。

## 6. AX 失败处理（FR-F1-006）

### 6.1 任何失败即终止 + 不回滚

arranging 阶段执行窗口移动操作时，任何窗口失败即立即终止本次编排：

- 任何窗口移动操作失败 → 立即停止后续排列
- **不回滚**已成功排列的窗口（保留新位置，新基线语义）
- 失败窗口保留在原位置
- 覆盖层显示失败原因（窗口标题 + 错误码）2 秒后自动消失
- 系统进入 idle 状态（窗口位置可能呈现半排列状态）
- 终止失败时记录日志，不崩溃

### 6.2 与 P0 探针策略的差异

P0 已实现"跳过 + >50% 终止"策略（失败数超过半数才终止 + 还原已排列窗口）。F1 需回退该策略并改为"任何失败即终止 + 不回滚"：

| 维度 | P0 策略 | F1 策略 |
|------|---------|---------|
| 失败阈值 | > N/2 | 任何失败（≥1） |
| 已排列窗口 | 还原到原始位置 | 保留新位置（不回滚） |
| 失败窗口 | 保留原位置 + 显示标签 | 保留原位置（不显示标签，因为编排已终止） |
| 后续行为 | 还原后进入 idle | 立即进入 idle（半排列状态） |
| 覆盖层 | 显示降级标签 | 显示失败原因 2 秒 |

### 6.3 风险提示

AX 失败在 Finder、系统设置、部分 Electron App 上不算罕见；本 FR 的严格策略会显著降低编排成功率，需在 F1 实现期实测失败率，若 >5% 重新评估本 FR（可能回退为"阈值终止"或"失败降级保留标签"策略）。

## 7. 用户可见错误（FR-F1-005 用户可见错误）

### 7.1 统一通过编排覆盖层

所有错误通过编排覆盖层显示，不新增独立弹窗组件。

### 7.2 错误内容与时长

- **错误内容**：窗口标题 + 错误码
- **显示时长**：2 秒后自动消失
- **位置**：覆盖层默认位置（中心偏上动态约束）

### 7.3 覆盖错误场景

| 场景 | 来源 FR | 触发时机 |
|------|---------|---------|
| AX 失败（arranging） | FR-F1-006 | 窗口移动操作失败时 |
| 激活失败（selecting） | FR-F1-003 | 激活操作抛异常时 |
| 10+ 窗口截断提示 | FR-F1-002 | 枚举窗口数 > 9 时 |

### 7.4 覆盖层扩展

P0 覆盖层只支持显示字母标签模式。F1 需扩展错误提示模式：

- **标签模式**：arranging → selecting 时显示字母标签
- **错误模式**：AX 失败 / 激活失败时显示错误文本
- **截断提示模式**：10+ 窗口时显示提示文本（与标签模式同时显示）

实现层通过扩展 OverlayShowing 协议增加 `showError(text:duration:)` 或类似方法。

## 8. 模块交互

### 8.1 selectWindow 时序（FR-F1-003）

```
用户按字母
  ↓
selectWindow(label):
  ├─ 校验 state == .selecting
  ├─ 校验 !isSelectingWindow
  ├─ 查找 layoutCells 中 label 对应的 cell
  ├─ isSelectingWindow = true
  ├─ stopSelectTimeout()
  ├─ eventTapManager.stopTap()  // 释放事件流，避免 AX 调用失败
  ├─ activateWindow(window):
  │   ├─ AX 设置 main/focused/raise/frontmost/focused
  │   ├─ CGEvent 模拟点击窗口中心
  │   └─ 返回结果
  ├─ if activateResult == .failed:
  │   ├─ isSelectingWindow = false
  │   ├─ overlay.showError(窗口标题 + 错误码, 2s)
  │   ├─ 保持 state == .selecting
  │   ├─ startSelectTimeout()  // 重置超时
  │   └─ startKeyEventTap()    // 重新拦截按键
  │   └─ return
  └─ DispatchQueue.main.asyncAfter(250ms):
      maximizeAfterActivate():
        ├─ 校验 state == .selecting（可能已退出）
        ├─ setFrame(screen.frame, window)  // 无内缩
        ├─ overlay.hideOverlay()
        ├─ state = .working
        └─ isSelectingWindow = false（defer）
```

### 8.2 working 热键时序（FR-F1-005）

```
用户按 Tidy 热键（state == .working）
  ↓
toggle():
  ├─ 校验 state == .working
  ├─ currentWindows = windowEnumerator.enumerateVisibleWindows(forPID: frontmostPID)
  ├─ snapshotWindowIDs = positionSnapshot.keys
  ├─ currentWindowIDs = currentWindows.map { $0.id }
  ├─ if Set(snapshotWindowIDs) == Set(currentWindowIDs):
  │   ├─ 取消放大：setFrame(layoutCell.frame, 放大窗口)  // 恢复到排列位置
  │   ├─ overlay.showOverlay(cells: layoutCells, on: targetScreenFrame)
  │   ├─ state = .selecting
  │   ├─ startSelectTimeout()
  │   └─ startKeyEventTap()
  └─ else:
      ├─ 清空旧快照：positionSnapshot = [:], arrangedWindows = []
      └─ activate()  // 走完整 arranging → selecting 流程
```

### 8.3 Session 快照存储

Session 快照扩展自 P0 的 `positionSnapshot: [CGWindowID: CGRect]`：

- **窗口标识集合**：`positionSnapshot.keys`（CGWindowID 集合）
- **原始位置**：`positionSnapshot[windowID]`（CGRect）
- **窗口信息列表**：`arrangedWindows: [WindowInfo]`（含 axRef 用于 AX 调用）
- **布局单元格列表**：`layoutCells: [LayoutCell]`（用于 working 热键集合相同时恢复放大窗口位置）

### 8.4 系统通知监听

F1 新增系统通知监听能力：

- **Space 切换**：监听 `NSWorkspace.activeSpaceDidChangeNotification`
- **App 切换**：监听 `NSWorkspace.didActivateApplicationNotification`（与 frontmostPID 比较）
- **App 退出**：监听 `NSWorkspace.didTerminateApplicationNotification`（与 frontmostPID 比较）

监听注册时机由实现层决定（AppDelegate 启动时 / 首次进入编排时）。监听回调根据当前状态按 4.1 矩阵处理。
