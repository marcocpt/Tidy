# P0_技术探针 手动验证清单

> 最后更新：2026-07-29 | 版本：v0.2
> 文档状态：执行中（MV-P0-008 已验证）
> 阶段定位：准备阶段 artifacts，不参与 F 功能编号

本文档汇总 P0_技术探针阶段所有需要手动验证的项，作为 XCUITest 自动化覆盖之外的人工证据载体。验证结果作为对应 AC 的判定依据。

## 1. 为什么需要手动验证

依据 [P0_02_设计文档](../P0_02_设计文档.md) 6.3 节 UI 测试分层，以下行为无法通过 XCUITest 稳定自动化，必须手动验证：

| 原因 | 涉及 AC |
|------|---------|
| **平台限制**：XCUITest 在 macOS 上无法访问 `NSStatusItem`（系统状态栏不在 App 的 accessibility hierarchy 中） | AC-P0-008 |
| **环境敏感**：跨 Space、窗口层级、鼠标穿透、多显示器等行为依赖真实显示环境 | AC-P0-007、AC-P0-010 |
| **权限依赖**：AX 权限、Input Monitoring 权限需要系统设置交互 | AC-P0-001、AC-P0-006、FR-P0-014 |
| **真实 App 依赖**：兼容性矩阵需要在真实第三方 App 上验证 | AC-P0-003、AC-P0-014、AC-P0-015、AC-P0-017 |
| **性能测量**：P95 指标需要多次真实运行并统计 | AC-P0-011 |

### 2.4 AC-P0-008 状态栏可用

| 验证 ID | MV-P0-008 | 状态 | ✅ 已验证 |
|---------|-----------|------|--------|
| **覆盖** | TC-P0-023、TC-P0-024 | **优先级** | 高 |

> **平台限制说明**：XCUITest 在 macOS 上无法访问 `NSStatusItem`（系统状态栏不在 App 的 accessibility hierarchy 中）。已通过 XCUITest 验证 App 启动不崩溃（`testAppLaunchesWithoutCrash`），但状态栏图标与菜单的可见性、可点击性必须手动验证。

**前置条件**：
- Tidy 探针已构建并运行

**验证步骤**：
1. **图标稳定显示（TC-P0-023）**：启动 Tidy，观察状态栏图标 "T" 是否稳定显示（不闪烁、不消失）
2. **菜单可点击（TC-P0-024）**：点击状态栏图标，确认下拉菜单出现
3. **菜单项完整（TC-P0-024）**：确认菜单包含"触发编排"与"退出"两项
4. **菜单项可触发回调（TC-P0-024）**：
   - 点击"触发编排"，确认编排流程被触发（观察 `os_log` 或窗口排列行为）
   - 点击"退出"，确认 App 退出

**预期结果**：
- 图标稳定显示不闪烁
- 菜单可点击
- 至少包含"退出"与"触发编排"菜单项
- 菜单项点击触发对应回调

**证据要求**：截图或录屏，记录图标、菜单、点击行为

**实际结果**：
- 构建版本：develop 分支 ab472b3 之后的修复版本（含 main.swift 入口点修复与 LSUIElement=true）
- 验证环境：macOS（具体版本见环境基线）
- 步骤 1（图标显示）：✅ 状态栏 "T" 图标稳定显示，不闪烁、不消失
- 步骤 2（菜单点击）：✅ 点击图标后下拉菜单完整出现
- 步骤 3（菜单项完整）：✅ 菜单包含"触发编排"与"退出"两项（中间有分隔线）
- 步骤 4（回调验证）：✅ "触发编排"成功触发编排流程，"退出"正常退出 App

**修复记录**：
- 发现根因：`@main` + `NSApplicationDelegate` 在无 main nib 时不会自动设置 delegate，导致 `applicationDidFinishLaunching` 从未被调用
- 修复方式：创建 `TidyApp/main.swift` 显式设置 `NSApplication.shared.delegate`；在 `project.yml` 添加 `LSUIElement: true` 使 App 作为 Menu Bar App 运行
- 验证方式：通过 NSLog 跟踪初始化流程，确认 `applicationDidFinishLaunching` → `StatusItemManager.setup` → 状态栏项创建成功

**判定**：✅ PASS
