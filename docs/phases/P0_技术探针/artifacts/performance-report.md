# P0_技术探针 性能报告

> 最后更新：2026-07-29 | 版本：v0.1
> 文档状态：草案（待填充验证证据）
> 阶段定位：准备阶段 artifacts，不参与 F 功能编号

本文档是 P0_技术探针 阶段的性能验证报告，覆盖 [P0_01_阶段需求与验收](../P0_01_阶段需求与验收.md) 5.1 节定义的性能门槛与 5.1.1 节性能测量协议。验证结果作为 AC-P0-011（排列时间达标）的判定依据。

## 1. 性能门槛

| 指标 | 门槛 | 来源 |
|------|------|------|
| 2 窗口排列完成时间 P95 | ≤ 800ms | 市场调研报告第七节继续开发门槛 |
| 5 窗口排列完成时间 P95 | ≤ 800ms | 同上 |
| 9 窗口排列完成时间 P95 | ≤ 800ms | 同上 |
| AX 设置窗口位置与大小成功率（First-attempt frame success） | ≥ 99% | 同上（兼容性矩阵 Tier A App） |
| 还原成功率（Session restore success） | ≥ 99% | 同上 |

## 2. 测量协议

依据 P0_01 5.1.1 节：

| 条件 | 要求 | 实际值 |
|------|------|--------|
| 参考机器 | MacBook Pro 14" 2021（M1 Pro）或同等性能 | 待填充 |
| macOS 版本 | macOS 12 Monterey | 待填充 |
| 冷/热启动 | 首次测量前 warm-up 3 次，正式样本至少 20 次 | 待填充 |
| 窗口数量 | 2、5、9 | 待填充 |
| App | Tier A App 各测一组 | 待填充 |
| 包含动画 | 是（覆盖层淡入、标签渲染） | 待填充 |

测量区间定义：
- `Arrange latency = T2 - T0`
- `T0` = 收到热键 callback
- `T1` = 所有需要移动的窗口完成 AXSetFrame
- `T2` = 标签可见且可接受输入

成功率指标定义：
- `First-attempt frame success` = 成功设置的窗口操作数 / 总窗口操作数
- `Session restore success` = 完整恢复全部预期窗口的会话数 / 总会话数

## 6. 测量方法

### 6.1 时间戳埋点

在 TidyOrchestrator 中添加 `os_log` 埋点：
- `T0`：热键 callback 触发时刻
- `T1`：所有窗口 AXSetFrame 完成时刻
- `T2`：覆盖层与标签可见且可接受输入时刻

### 6.2 数据收集

每次排列记录一行 CSV：
```text
timestamp,app,window_count,t0_ms,t1_ms,t2_ms,arrange_latency_ms,frame_success_count,frame_total_count,restore_success
```

### 6.3 统计方法

- 至少 20 次正式样本（warm-up 3 次后）
- P95 = 第 95 百分位数（按升序排序后取 ceil(0.95 * n) 位置）
- 成功率 = 成功次数 / 总次数
