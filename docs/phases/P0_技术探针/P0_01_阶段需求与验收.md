# P0_技术探针 阶段需求与验收

> 最后更新：2026-07-29 | 版本：v0.3
> 文档状态：P0 Exit Gate 条件性通过（2026-07-29）
> 阶段定位：准备阶段（不参与 F 功能编号）；P0 Exit Gate 通过后才开始 F0_权限引导等功能阶段

本文档是 P0_技术探针 阶段的需求合同与验收依据。技术验证项与项目骨架范围以 [docs.md](../../docs.md) 第 4.4 节为准；性能门槛与兼容性矩阵以 [Tidy 窗口管理 App 市场调研报告](../../Tidy%20窗口管理%20App%20市场调研报告.md) 第七节为准；模块组织、状态机与 AX 行为细节参见 [Tidy 窗口管理 App 功能列表](../../Tidy%20窗口管理%20App%20功能列表.md)。

> **维度说明**：本文档中的"P0"指**准备阶段编号**（与 [docs.md](../../docs.md) 第 3.1 节定义的 `P{n}_` 准备阶段前缀一致）；[Tidy 窗口管理 App 功能列表](../../Tidy%20窗口管理%20App%20功能列表.md)中的"P0/P1/P2"指**功能优先级**（Priority），是独立维度。两者不可混淆。

模块职责、数据流、状态机、错误回退与 SPM 骨架设计见同目录 [P0_02_设计文档](P0_02_设计文档.md)。

## 1. 目标（Goal）

P0_技术探针 是 Tidy 的准备阶段，目标有三：

1. **证明核心技术栈可行**：验证 AX 窗口枚举与操作、Carbon 全局热键、CGEventTap 输入拦截、NSPanel 覆盖层、NSStatusItem 状态栏、自适应网格布局、多显示器坐标等关键能力在目标平台与目标 App 上可稳定工作；
2. **建立可编译的 SPM 骨架**：完成 `TidyCore` / `TidyUI` / `TidyApp` 三 target 骨架，可编译、可运行探针、可通过 SwiftLint `--strict`；
3. **为 F0~F5 功能阶段扫清技术风险**：产出兼容性矩阵、性能基线与失败降级策略，使 F1_窗口编排核心 可直接基于已验证组件进入实现，无需重复技术探针。

P0 不交付面向终端用户的可用产品，只交付技术证据与项目骨架。P0 Exit Gate 通过后，技术可行性已证明、骨架可编译，才允许创建 `F0_01_阶段需求与验收.md`。

## 2. 范围（Scope）

P0 集中承载以下技术验证与项目骨架（对应 [docs.md](../../docs.md) 第 4.4 节技术风险验证矩阵）：

| 类别 | 验证项 |
|------|--------|
| 权限 | AX 授权状态检测与监听 |
| 枚举 | 基于 CGWindowList 与 AX 匹配的窗口枚举 |
| 操作 | AX 设置窗口位置与大小的兼容性（多 App 成功率与重试） |
| 操作 | AX 获取焦点窗口 |
| 输入 | Carbon 全局热键注册 |
| 输入 | CGEventTap 创建、启用、禁用与恢复的生命周期 |
| UI | NSPanel 覆盖层（层级、跨 Space、鼠标穿透） |
| UI | NSStatusItem 状态栏图标与菜单 |
| 算法 | 自适应网格布局算法 |
| 显示 | 多显示器坐标（双屏 / 三屏场景） |
| 性能 | 2 / 5 / 9 窗口排列完成时间 P95 |
| 工程 | SPM 三 target 骨架（TidyCore / TidyUI / TidyApp）可编译 |
| 工程 | SwiftLint 配置（`.swiftlint.yml`）建立并通过 `--strict` |

P0 需求与设计文档应包含完整的兼容性验证矩阵与性能门槛。P0 期间允许探索首批 ADR 主题（依赖方向、激活模型、窗口范围、目标屏幕、还原语义、CGEventTap 生命周期、AXSetFrame 失败处理、偏好窗口技术选型、字母标签位置），在 F1 验证后冻结为正式 ADR。

## 3. Out of Scope

以下内容不属于 P0，留待后续功能阶段：

- **完整功能实现**：F1 窗口编排核心的完整 5 状态机、偏好设置驱动、端到端用户流程；

- **自定义布局模板**：用户保存与切换布局模板（F3）；
- **循环切换**：working 阶段窗口循环切换（F4）；
- **跨 App 编排**：多 App 窗口聚合编排（F5）；
- **权限引导窗口**：首次启动权限引导 UI（F0）；
- **完整状态栏菜单**：5 项菜单与 4 种图标状态的完整交互（F0.1）；

## 4. 功能需求（FR）

为每项技术验证定义 FR 编号（FR-P0-001 起）。每条 FR 包含验证项、验证方法、预期结果。FR 仅描述"验证什么"与"预期结果"，不规定模块划分、数据结构或实现步骤（那是设计文档的职责）。

### FR-P0-001 AX 权限检测

- **验证项**：检测辅助功能权限授权状态，并能在用户授权后感知状态变化。
- **验证方法**：在未授权、已授权两种状态下分别查询；授权状态变化时能被探针感知（不轮询）。
- **预期结果**：能正确区分"未授权"与"已授权"两种状态；授权状态变化后探针能感知并更新内部状态，无需重启探针。

### FR-P0-002 AX 窗口枚举

- **验证项**：枚举前台 App 在当前 Space 上的所有可见窗口，并与 AX 窗口引用匹配。
- **验证方法**：在 Xcode、Finder、Safari 等目标 App 上分别打开 2、5、9 个窗口，触发枚举，核对枚举结果与实际可见窗口数量。
- **预期结果**：枚举数量准确；排除菜单栏、Dock、覆盖层等非普通窗口；每个窗口可获得用于后续位置与大小操作的引用；仅 0 或 1 个可见窗口时能正常处理。

### FR-P0-003 AX 窗口位置与大小设置兼容性

- **验证项**：通过 AX 设置窗口位置与大小，验证多 App 成功率与重试行为。
- **验证方法**：在兼容性矩阵覆盖的每个 App 上，对 2、5、9 个窗口分别设置新位置与大小，记录成功率、失败窗口数、是否需要重试。
- **预期结果**：兼容性矩阵内主流 App（Xcode、VSCode、Finder、Safari、Chrome、Office、JetBrains、Adobe）成功率满足 NFR 门槛；单个窗口失败时跳过且不阻塞其他窗口；失败窗口数超过半数时终止本次编排。

### FR-P0-004 AX 焦点窗口获取

- **验证项**：获取前台 App 的焦点窗口，用于判定目标屏幕。
- **验证方法**：在前台 App 切换焦点窗口后触发获取，核对结果与实际焦点窗口。
- **预期结果**：能正确获取焦点窗口引用；无焦点窗口时返回空并走兜底屏幕。

### FR-P0-005 Carbon 全局热键注册

- **验证项**：注册全局热键（默认 ⌘⌥T），并在热键按下时收到回调。
- **验证方法**：注册热键后，在不同前台 App（含全屏 App）下按热键，确认回调被触发；测试热键冲突场景。
- **预期结果**：热键在前台任意 App 下均可触发回调；应用退出时热键注销；热键冲突时能检测并记录。

### FR-P0-006 CGEventTap 生命周期

- **验证项**：CGEventTap 的创建、启用、禁用与禁用后恢复。
- **验证方法**：创建事件拦截；启用后拦截键盘事件；模拟系统超时禁用与用户输入禁用，验证自动恢复；验证恢复失败时的降级。
- **预期结果**：能在需要时启用拦截、在结束时禁用；超时禁用与用户输入禁用后能自动恢复；恢复失败时能安全退出拦截状态并还原窗口，不崩溃。

### FR-P0-007 NSPanel 覆盖层

- **验证项**：NSPanel 覆盖层的层级、跨 Space 可见性与鼠标穿透。
- **验证方法**：在目标屏幕创建覆盖层，验证其层级高于普通窗口、低于系统菜单；切换 Space 验证仅当前 Space 可见；验证鼠标事件穿透到下层窗口。
- **预期结果**：覆盖层不抢焦点、不拦截鼠标；层级正确；跨 Space 行为符合预期；覆盖范围为目标屏幕可见区域（不遮挡菜单栏）。

### FR-P0-008 NSStatusItem 状态栏

- **验证项**：状态栏图标显示与菜单点击。
- **验证方法**：启动后状态栏图标可见；点击显示下拉菜单；菜单项可点击并触发回调。
- **预期结果**：图标稳定显示不闪烁；菜单可点击；P0 至少包含"退出"与一个触发探针的菜单项。

### FR-P0-009 自适应网格布局算法

- **验证项**：根据窗口数量与屏幕长宽比计算非重叠网格布局。
- **验证方法**：对 2、5、9、16、26 个窗口分别计算布局，核对网格行列数、单元格不重叠、单元格铺满可见区域。
- **预期结果**：网格行列数随窗口数量与屏幕长宽比自适应；单元格互不重叠；窗口数超过 26 时仅取前 26 个并提示；宽屏与竖屏均能给出合理布局。

### FR-P0-010 多显示器坐标

- **验证项**：双屏 / 三屏场景下的目标屏幕判定与坐标正确性。
- **验证方法**：在双屏与三屏环境下，将焦点窗口置于不同屏幕，触发探针，核对目标屏幕判定与窗口坐标是否落在目标屏幕可见区域内。
- **预期结果**：目标屏幕基于焦点窗口中心判定；坐标在目标屏幕可见区域内（排除 Dock 与菜单栏）；边界窗口（跨屏）能正确归属；无焦点窗口时走兜底屏幕。

### FR-P0-011 排列完成时间

- **验证项**：2、5、9 个窗口的排列完成时间。
- **验证方法**：在兼容性矩阵覆盖的 App 上，分别对 2、5、9 个窗口触发完整排列流程，记录从触发到排列完成的耗时，计算 P95。
- **预期结果**：2、5、9 窗口排列完成时间 P95 满足 NFR 门槛（≤ 800ms）。

### FR-P0-012 SPM 三 target 骨架

- **验证项**：`TidyCore` / `TidyUI` / `TidyApp` 三 target 骨架可编译、可运行探针。
- **验证方法**：执行 SPM 构建命令；运行探针入口；核对依赖方向（`TidyCore` 不依赖 AppKit）。
- **预期结果**：三 target 可编译通过；探针可运行；`TidyCore` 不引入 AppKit 依赖；`TidyUI` 依赖 `TidyCore`；`TidyApp` 依赖两者。

### FR-P0-013 SwiftLint 配置

- **验证项**：`.swiftlint.yml` 建立并通过 `--strict` 检查。
- **验证方法**：在仓库根目录执行 SwiftLint `--strict` 检查。
- **预期结果**：所有 error 与 warning 级违规清零；第三方依赖与生成代码通过 `excluded` 排除；配置文件位于仓库根目录。

### FR-P0-014 Input Monitoring / Event Access 权限矩阵

- **验证项**：验证 Accessibility 与 Input Monitoring 两种权限在不同组合下对 CGEventTap 创建、键盘事件接收与事件消费的影响。
- **验证方法**：在 Accessibility OFF/ON × Input Monitoring OFF/ON 的 4 种组合下，分别尝试创建 CGEventTap（.cgSessionEventTap + .defaultTap）、接收键盘事件、消费事件（拦截后不传递），记录每种组合的成功/失败/降级结果。
- **预期结果**：产出完整的权限矩阵（4×3），明确 F0 权限引导需要引导用户授权哪些权限；若 Accessibility 单独授权即可完成全部事件操作，则 Input Monitoring 不作为必需权限。

## 5. 非功能需求（NFR）

### 5.1 性能门槛

| 指标 | 门槛 | 来源 |
|------|------|------|
| 2 窗口排列完成时间 P95 | ≤ 800ms | 市场调研报告第七节继续开发门槛 |
| 5 窗口排列完成时间 P95 | ≤ 800ms | 同上 |
| 9 窗口排列完成时间 P95 | ≤ 800ms | 同上 |
| AX 设置窗口位置与大小成功率（First-attempt frame success） | ≥ 99% | 同上（兼容性矩阵 Tier A App） |
| 还原成功率（Session restore success） | ≥ 99% | 同上 |

性能门槛是 P0 Exit Gate 的硬约束。任一指标不达标时，P0 不得通过，需先排查根因（AX 兼容性、批次策略、重绘抖动等）并修复。

### 5.1.1 性能测量协议

P95 指标需在以下条件下测量：

| 条件 | 要求 |
|------|------|
| 参考机器 | MacBook Pro 14" 2021（M1 Pro）或同等性能 |
| macOS 版本 | macOS 12 Monterey |
| 冷/热启动 | 首次测量前 warm-up 3 次，正式样本至少 20 次 |
| 窗口数量 | 2、5、9 |
| App | Tier A App 各测一组 |
| 测量区间 | Arrange latency = T2 - T0，其中 T0 = 收到热键 callback，T1 = 所有需要移动的窗口完成 AXSetFrame，T2 = 标签可见且可接受输入 |
| 包含动画 | 是（覆盖层淡入、标签渲染） |

成功率指标定义：

- **First-attempt frame success** = 成功设置的窗口操作数 / 总窗口操作数
- **Session restore success** = 完整恢复全部预期窗口的会话数 / 总会话数

### 5.2 兼容性矩阵覆盖

P0 兼容性验证按 Tier 组织：

**Tier A — Exit Gate 硬门槛**

| App | 类别 | 必须验证 |
|-----|------|----------|
| Xcode | 原生 macOS | 枚举、设置 frame、焦点窗口 |
| VS Code | Electron | 同上 |
| Finder | 原生 macOS | 同上 |
| Safari | 原生浏览器 | 同上 |
| Chrome | Electron / 浏览器 | 同上 |

Tier A App 必须达到硬门槛：AX 成功率 ≥ 99%、排列时间 P95 ≤ 800ms。

**Tier B — Compatibility Evidence**

| App | 类别 | 必须验证 |
|-----|------|----------|
| JetBrains IDE | JVM | 枚举、设置 frame、焦点窗口 |
| Microsoft Office | 原生 / 混合 | 同上 |
| Adobe 常用应用 | 原生 / 混合 | 同上 |

Tier B App 必须测试、必须记录，但允许标注 `PASS` / `LIMITED` / `LABEL_ONLY` / `UNSUPPORTED`，不阻塞 P0 Exit Gate。

每个 App 至少记录：2、5、9 个窗口的排列时间、设置位置与大小的成功率、是否产生重复跳动或明显重绘、临时放大与恢复的成功率、AX 失败时降级是否仍可选择。

兼容性矩阵结果保存到 `artifacts/`（清单、矩阵、证据），不写入本需求文档。

### 5.3 可编译性与工程约束

- SPM 三 target 骨架可编译通过；
- `TidyCore` 不引入 AppKit 依赖（编译器层面拒绝）；
- 探针代码可运行；
- 目标平台 macOS 12（Monterey）及以上；
- 开发工具 Xcode 14.1+ / Swift 5.7+。

### 5.4 代码质量

- SwiftLint `--strict` 通过（error 与 warning 级违规清零）；
- 第三方依赖与生成代码通过 `excluded` 排除；
- `.swiftlint.yml` 位于仓库根目录。

## 6. Acceptance Criteria

每条 AC 有编号（AC-P0-001 起），可测，引用对应 FR。

### AC-P0-001 AX 权限检测可用

- **Given** 探针已启动且辅助功能权限处于"未授权"或"已授权"状态；
- **When** 查询权限状态，或用户在系统设置中切换授权状态；
- **Then** 探针能正确返回当前状态，且授权状态变化后能感知并更新内部状态（无需重启）；
- **覆盖**：FR-P0-001。

### AC-P0-002 窗口枚举准确

- **Given** 目标 App 在当前 Space 上有 2、5、9 个可见窗口；
- **When** 触发窗口枚举；
- **Then** 枚举数量与实际可见窗口一致，排除菜单栏 / Dock / 覆盖层，每个窗口可获得后续操作引用；
- **覆盖**：FR-P0-002。

### AC-P0-003 AX 设置 frame 成功率达标

- **Given** 兼容性矩阵内主流 App（Xcode、VSCode、Finder、Safari、Chrome、Office、JetBrains、Adobe）已打开 2、5、9 个窗口；
- **When** 触发排列并对每个窗口设置新位置与大小；
- **Then** 成功率 ≥ 99%；单个窗口失败时跳过且不阻塞其他窗口；失败窗口数超过半数时终止本次编排；
- **覆盖**：FR-P0-003、NFR 5.1。

### AC-P0-004 焦点窗口获取正确

- **Given** 前台 App 有焦点窗口；
- **When** 获取焦点窗口；
- **Then** 返回的窗口引用与实际焦点窗口一致；无焦点窗口时返回空并走兜底屏幕；
- **覆盖**：FR-P0-004。

### AC-P0-005 全局热键可触发

- **Given** 全局热键已注册（默认 ⌘⌥T）；
- **When** 在不同前台 App（含全屏 App）下按热键；
- **Then** 回调被触发；应用退出时热键注销；热键冲突时能检测并记录；
- **覆盖**：FR-P0-005。

### AC-P0-006 CGEventTap 生命周期可控

- **Given** CGEventTap 已创建；
- **When** 启用拦截、禁用拦截、模拟系统超时禁用与用户输入禁用；

## 7. 决策自由度（Decision Freedom）

### 7.1 P0 期间可自由决定的技术细节

以下细节在 P0 期间可由探针实现者自由决定，不阻塞 Exit Gate，也不需要写 ADR：

- **探针代码组织方式**：探针可放在测试 target、独立可执行 target 或临时脚本中，不强制与生产代码同结构；
- **探针触发方式**：可用菜单项、命令行参数、单元测试或临时热键触发，不强制最终用户交互；
- **日志格式**：P0 探针日志可用 `os_log` 或 `print`，只要能产出验证证据；生产化日志规范在 standards 建立时确定；
- **测试 target 划分**：探针测试可归入单元测试或集成测试，不强制最终测试 target 结构；
- **验证证据格式**：兼容性矩阵、性能数据可用 Markdown、CSV 或 JSON，只要保存到 `artifacts/` 且可追溯；
- **临时硬编码**：探针允许临时硬编码窗口数量、App 列表、屏幕 ID 等参数，不要求配置化；
- **覆盖层视觉细节**：字母标签字体、颜色、位置在 P0 仅验证可行性与不遮挡，最终视觉规格在 F1 视觉原型确定。

### 7.2 P0 期间必须先决策的架构主题

以下主题必须在 P0 期间探索并给出倾向性结论，在 F1 验证后冻结为正式 ADR（对应 [docs.md](../../docs.md) 第 7 节 ADR 主题清单）。P0 不要求冻结最终决定，但要求产出验证证据与倾向方案，避免 F1 期间返工：

| 主题 | 必须在 P0 期间回答的倾向问题 | 对应 FR |
|------|------------------------------|---------|
| 依赖方向 | `TidyCore` / `TidyUI` / `TidyApp` 三 target 划分是否可行；`TidyCore` 不依赖 AppKit 是否会阻塞关键能力 | FR-P0-012 |
| 激活模型 | 单热键 Toggle 是否足以覆盖核心流程；是否需要多激活方式 | FR-P0-005 |
| 窗口范围 | 当前 Space 可见窗口是否足够；跨 Space 聚合是否必要 | FR-P0-002 |
| 目标屏幕 | 焦点窗口所在屏是否合理；边界窗口如何归属 | FR-P0-010、FR-P0-004 |
| 还原语义 | 撤销排列（无视 working 阶段手动操作）是否可行；是否需要追踪手动操作 | FR-P0-003、FR-P0-011 |
| CGEventTap 生命周期 | 仅 selecting 阶段启用是否足够；全程常驻是否有必要 | FR-P0-006 |
| AXSetFrame 失败处理 | "跳过 + >50% 终止"与"原位置标签降级"两种策略的取舍 | FR-P0-003 |
| 偏好窗口技术选型 | `NSWindow + SwiftUI content` 是否稳定；与 NSPanel 集成是否有已知问题 | FR-P0-012 |
| 字母标签位置 | 窗口左上角内侧与中心偏上动态约束两种方案的取舍（注意市场调研报告建议中心偏上以避开系统按钮） | FR-P0-007 |

P0 期间对这些主题的探索结果记录到 `artifacts/` 或 ADR 草案，不写入本需求文档的结论部分。最终冻结的 ADR 在 F1 验证后产出。
